# 마이팀 제품 기획 초안

## 1. 제품 개요

- **제품명:** 마이팀
- **주제:** 아마추어 축구팀 관리 및 경기 진행 지원
- **형태:** 웹 기반 반응형 앱. 모바일에서는 웹뷰 형태로 운영하고 배포하는 것을 고려한다.
- **구성:** `apps/web`과 `apps/api`로 구성된 모노레포
- **핵심 목표:** 매주 열리는 조기축구 경기에서 총무나 감독이 출석 인원을 확인하고 쿼터별 라인업을 짜는 시간을 줄인다.
- **주요 사용자:** 팀 총무, 감독 및 팀원. 로그인 사용자 역할에 따라 이용 가능한 기능과 화면이 달라지는 방향이다.

## 2. 해결하려는 문제

경기 전마다 참석자와 용병이 달라지고, 선수별 출전 기회와 선호 포지션을 고려해 라인업을 구성해야 한다. 이 과정을 빠르게 진행하고, 지난 경기의 라인업을 재사용하거나 당일 상황에 맞게 수정할 수 있도록 돕는다.

## 3. 핵심 기능

### 3.1 선수 관리

선수 정보를 등록하고 관리한다.

- 이름
- 나이
- 선호 포지션 최대 3개
- 선호 포지션 선택지에 `포지션 상관없음` 포함
- 회원 / 용병 여부
- 선수 스탯 및 특징은 향후 입력 기능으로 추가한다. 세부 항목이 정해지기 전까지 등록 화면에 노출하지 않는다.
- 경기 참석 여부는 경기 편성 흐름에서 선택한다.

### 3.2 전술판

- 기본 진입 화면은 전술판과 쿼터별 라인업이다. 별도 소개 화면 없이 경기 배치부터 보여준다.
- 저장된 선수와 참석 정보가 있으면 첫 화면에서 현재 설정으로 라인업을 바로 생성한다.
- 참석자나 경기 설정이 바뀌면 배치를 다시 계산해 전술판을 최신 상태로 유지한다.
- 선수 명단이 비어 있으면 간단한 선수 등록 동작을 보여준다.
- 사용자가 전술판에서 배치 결과를 확인하고 필요에 따라 조정할 수 있는 방향이다.
- 선수 관리 화면으로 이동하는 진입점을 제공한다.
- 현재 프로토타입은 브라우저 저장소를 사용한다. 여러 기기 간 공유와 계정 기반 저장은 백엔드 연결 후 구현한다.

### 3.3 오늘의 라인업 편성

이전 라인업과 당일 참석자가 다를 수 있으므로 전술판에서 **오늘의 라인업 짜기**를 시작한다.

편성 입력 흐름:

1. 경기 유형 선택: 자체전 또는 팀매치전
2. 쿼터 수 선택
3. 선수별 최소 참여 쿼터 수 선택
4. 포메이션 선택 방식 지정
   - 모든 쿼터에 같은 포메이션
   - 쿼터별 포메이션 지정
   - 랜덤 또는 알고리즘 추천
5. 포메이션에 맞춰 선수 자동 배치

초기 구현은 팀매치용 한 팀 라인업 생성에 집중한다. 자체전 팀 나누기 규칙은 별도 기획 후 추가한다.

경기 유형에 따라 팀을 나누는 방식 등 세부 규칙은 추후 정의한다.

## 4. 자동 배치 기준 초안

배치는 다음 우선순위를 고려한다.

1. **누적 출전 쿼터 수:** 현재 경기에서 상대적으로 적게 뛴 선수를 우선 배치한다.
2. **선호 포지션:** 1지망, 2지망, 3지망 순으로 고려한다.
3. **유사 포지션:** 선호 포지션 자리가 없으면 같은 계열의 다른 포지션을 고려한다.
4. **잔여 자리:** 적합한 선호·유사 포지션 자리가 없으면 남은 선수 중 배치한다.

포지션 계열 초안:

| 계열     | 포지션                                          |
| -------- | ----------------------------------------------- |
| 공격형   | 윙어, 톱                                        |
| 미드필더 | 수비형 미드필더, 일반 미드필더, 공격형 미드필더 |
| 수비형   | 센터백, 사이드백, 골키퍼                        |

예: 윙어를 선호하는 선수에게 윙어 자리가 없으면 톱을 대안으로 고려한다.

알고리즘의 세부 점수, 동점 처리, 포지션 간 유사도, 골키퍼 배치 규칙, 수동 수정 후 재배치 동작은 추가 정의가 필요하다.

## 5. 주요 사용자 흐름

### 5.1 앱 진입

1. 로그인한 사용자가 앱에 들어온다.
2. 기본 화면으로 전술판을 보여준다.
3. 저장된 과거 배치가 있으면 우선 불러와 참고용으로 표시한다.
4. 당일 참석자가 다르거나 용병이 있으면 **오늘의 라인업 짜기**를 선택한다.
5. 기록이 없으면 빈 전술판을 보여주고 라인업 편성 또는 선수 등록으로 안내한다.

### 5.2 선수 등록

1. 전술판에서 선수 관리 화면으로 이동한다.
2. 선수 정보를 폼에 입력하고 등록한다.
3. 등록된 선수는 이후 경기 라인업 편성에서 선택할 수 있다.

## 6. 권한 및 역할

로그인 사용자의 역할에 따라 앱 화면과 기능을 달리한다는 방향만 정해져 있다. 역할 종류, 역할별 권한, 팀 가입·초대 방식은 추후 결정한다.

## 7. MVP 범위 제안

초기 버전은 매주 라인업을 만드는 핵심 흐름에 집중한다.

- 팀 선수 등록 및 기본 정보 편집
- 전술판에서 포메이션과 선수 배치 확인
- 경기 유형, 쿼터 수, 최소 참여 쿼터 수 설정
- 기본 자동 배치와 결과 조정
- 이전 라인업 불러오기 및 당일 라인업 저장
- 로그인과 역할 기반 접근의 최소 구조

### 7.1 제품 방향과 후속 확장

마이팀은 팀 관리, 팀 성장, 훈련 참여와 경기 운영을 돕는 서비스로 확장한다. 초기 중심 기능은 쿼터별 라인업 생성과 포메이션 배치다.

- 팀이 관리하는 선수 특징과 스탯을 바탕으로 일반 경기 및 대회 라인업·포메이션 후보를 추천한다.
- 대회별 연령 규칙을 설정하고 규정에 맞는 라인업을 추천한다. 적용 규정과 시즌은 사용자가 확인할 수 있어야 한다.
- 팀 목표, 훈련 참여, 시즌 기록 등 성장 및 게이미피케이션 기능을 추가할 수 있다.
- 이후 상대 팀 정보를 입력해 대응 전술을 제안하는 기능을 검토한다.
- LLM/AI 추천과 상대 분석은 세부 요구사항이 정해지지 않은 후속 방향이며, MVP 범위에는 포함하지 않는다.

### 7.2 반응형 디자인 시스템

- PC, 태블릿, 모바일 화면을 모두 지원한다.
- 메인/서브/포인트 색상, 텍스트 색상, 폰트 크기·굵기, 공용 컨테이너 너비를 디자인 토큰과 공용 컴포넌트로 관리한다.
- 브레이크포인트는 Tailwind 기본 기준을 사용한다: 기본 모바일, `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px, `2xl` 1536px.
- 넓은 화면에서는 설정과 전술판을 나란히 보여주고, 작은 화면에서는 조작 순서에 맞춰 세로로 배치한다.
- 모바일 웹뷰로 포장하는 배포 방식과 기기 지원 범위는 추후 결정한다.

구체적인 MVP 범위와 우선순위는 제품 기획 과정에서 확정한다.

## 8. 추후 결정할 항목

- 선수 스탯 및 특징의 구체적인 항목과 입력 방식
- 역할 종류와 역할별 권한
- 로그인, 팀 생성·가입·초대 방식
- 참석 여부 및 경기별 용병 추가 흐름
- 자체전과 팀매치전의 팀 구성 규칙
- 포메이션 목록과 포지션별 인원 정의
- 쿼터 교체 및 선수별 최소 출전 보장 방식
- 자동 배치 점수와 동점 처리, 포지션 유사도
- 전술판에서 수동으로 수정한 결과의 저장·재배치 규칙
- 이전 라인업을 불러올 기준과 저장 기록의 단위
- 모바일 웹뷰 배포 방식 및 지원 기기 범위
